JBJ Pricing Manager

The one place to view and update every price, formula number, and setting of the custom ring designer.

How this works — read me first

All the numbers the ring designer uses — prices, metal formulas, catalog, builder settings — live in one data record in Cloudflare KV (Cloudflare's online storage). The ring designer and the price engine read that record live. The script files never change when numbers change — publishing from this page is all it takes.

  1. Download live data — enter the API key and click "Download live data". The key is needed for downloading as well as uploading, and it is never saved anywhere; re-enter it each visit.
  2. Edit — open any section below and change values. Everyday numbers have their own labeled boxes with an explanation of what each one does. The big tables are edited as raw JSON text.
  3. Download a backup — always save a backup file before uploading, so you can restore if needed.
  4. Check & upload — pick a new version number, click "Check everything", review the list of changed sections, then upload. The server re-checks everything too; an invalid upload is rejected and the live data stays untouched.

Changes go live for customers within about an hour (browser caching).

Step 2 — Everyday settings (one box per value)

Formula constants — the metal-pricing math edited

These numbers drive the precious-metal price formula. Each one is explained below its box: what it is, where the value comes from, where it is used, and why it matters. Change with care — a few are universal constants that must never change.

Misc costs — the six fixed adders edited

Six fixed dollar adders. Exactly one base metal adder applies to every ring (chosen by whether the base metal is precious or not); the inlay adders are added when the design has inlay strips; the sleeve adders are added when the sleeve differs from the base. They appear as labeled lines in the staff price breakdown.

Spot-price safety ranges edited

Sanity limits for the live market feed, in $ per troy ounce. A fetched spot price at or outside its range is rejected and the last-known-good price is kept. "Min" and "max" are exclusive bounds: the price must be strictly between them.

Quote settings edited

How the quote Worker verifies incoming quote requests: the allowed price drift between what the customer saw and the server recalculation, and rate limiting.

Service addresses & timing edited

Where the designer finds its Workers, plus caching and retry timing. Only change addresses if a Worker is redeployed under a new name.

Business info & links edited

Brand name, support email, page links used in quotes and emails, and the quoted turnaround time.

Ring builder numbers — sizes, limits, timings, 3D view edited

The designer's numeric settings: ring size / width / strip ranges, input limits, UI timing, and the 3D ring view. The builder's lists and rules (steps, profiles, finishes, rules…) are edited in the raw JSON tables further down.

Payload description & other top-level values edited

The payload's own description text and remaining top-level numbers.

Advanced tables (raw JSON)

These are the big tables, edited as raw JSON text. Rules of thumb: keep the overall shape ({ } stays { }, [ ] stays [ ]), keep quotes around names, and no comma after the last item. Use Check JSON after editing — it tells you exactly what is wrong — and Format to tidy the layout. Nothing is uploaded until Step 3.

Step 3 — Check, back up, and upload

"Check everything" runs the same validation the server runs and lists which sections you changed. Always download a backup before uploading.
